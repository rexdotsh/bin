# AGENTS.md

bin: an agent-first pastebin at bin.rex.wf. One Cloudflare Worker, one R2 bucket (`bin-apac`, APAC location hint, R2 Local Uploads on), a zero-dependency CLI and a skill. Built like tack (`~/tack`), which serves HTML docs; bin only ever serves text.

## Layout

- `src/worker.ts`: the whole Worker (create, read, slices, digest, compare, delete, page shells). Pages inline `dist/bin.css` (imported as text via the `**/*.css` rule in `wrangler.jsonc`), plus `dist/md.css` on markdown pages only.
- `web/`: browser code, bundled by `bun run build` into static assets: `view.ts` (the paste viewer: rendering, ANSI colours, highlighting, selection, keyboard, unlock), `compose.ts` (the new-paste page), `crypto.ts` (shared PBKDF2 + AES-GCM), `hl.ts` + `hl-worker.ts` (highlight.js, lazy-loaded; auto-detection and big texts run in a module Worker), `md.ts` + `md.css` (the formatted markdown view, lazy-loaded), `edit.ts` (the in-place editor, lazy-loaded), `ui.ts` (toast, best-effort storage and cookies), `theme.ts`, `bin.css`.
- `src/page.ts` and `src/text.ts` are shared by the Worker and the browser (no DOM or Worker APIs): the viewer shell and asset names, and ANSI/`\r` stripping (`stripAnsi` is the server's; `toLines` gives the same text line by line).
- `cli/bin.ts`: the whole CLI, zero dependencies, Node built-ins only and erasable TypeScript only (runs as-is on Node 22.18+ and Bun; bundled to `dist/cli` for Node 20+).
- `skill/bin/SKILL.md`: the agent skill. `public/llms.txt`: plain-text usage, also what `GET /` returns to non-browsers.
- `scripts/import.ts`: one-off import of the old wastebin export (`bin-export*` is gitignored; never commit it, it holds other people's pastes).
- `scripts/build.ts`: the whole build: CLI bundle, browser bundles with hashed names, highlight.js split per language (the list comes from `EXT_LANG`), `view.ts` built twice (`view.js` with `MD=false`, so the markdown code is dropped, and `view-md.js` for markdown pages), `edit.js` (the editor, loaded on demand), `md.js` (marked's `Lexer` only: a build plugin cuts marked's bundle after the classes so its `Parser`/`Renderer`/`marked` instance are tree-shaken; marked is pinned, the plugin loads any file from the marked package and throws if the bundle's shape changes, and the build fails if the plugin never ran, e.g. if Bun resolved marked's UMD `browser` build), Geist subset into core + `unicode-range` ext files with metric-matched fallbacks, minified CSS (`bin.css`, and `md.css` both at the root for the Worker and hashed under `/a/` for compose), `_headers`, and a check that `dist/` holds exactly the expected files.
- `wrangler.jsonc`: Worker config. Deployed from the Cloudflare dashboard via GitHub, so it's the source of truth. `dist/` is served as static assets before the Worker (`/cli`, `/install`, `/skill.md`, `/llms.txt`, `/robots.txt`, `/favicon.ico`, `/favicon.svg`, hashed `/fonts/*`, and the browser JS under `/a/`). Static assets never reach the Worker, so `harden()` doesn't apply to them; `_headers` sets their cache headers. Browser JS (`view`, `compose`, highlight.js core, languages and `auto`) gets content-hashed names under `/a/` with immutable caching; `dist/assets.json` (not uploaded, see `.assetsignore`, which also skips `bin.css` and `md.css` since pages inline them) maps `view.js` to `/a/view.<hash>.js` and is bundled into the Worker and the browser code through `asset()` in `src/page.ts`. A stale hashed name under `/a/` (`.js` or `.css`) or `/fonts/` (an old cached page after a deploy) gets a 307 to the current file.

## Commands

```sh
bun install
bun run check     # wrangler types + tsc for worker, cli and web
bun run build     # dist/; fails unless it holds exactly the expected files
printf 'BIN_TOKEN=dev\n' > .dev.vars
bun run dev       # local worker on :8787 (from a generated wrangler.dev.json without routes) with local R2 and rate limiters
echo hi | curl --data-binary @- http://127.0.0.1:8787
BIN_URL=http://127.0.0.1:8787 XDG_CONFIG_HOME=/tmp/bin-cfg ./cli/bin.ts file.ts
```

There are no automated tests. Verify against `bun run dev` with curl, the CLI and a browser. `bun run dev` runs `bun run build` on start (the `build.command` in `wrangler.jsonc`), which recreates `dist/`; don't run two dev servers from the same checkout. Never run `bin setup` without `--token` while testing (it sets the secret on the real Worker), and don't run wrangler commands that touch Cloudflare.

## Rules

- Bun for repo tooling. No npm/npx.
- The CLI must not depend on Bun (no `Bun.*`, no top-level await, erasable syntax only). Check with `node cli/bin.ts` and `bun run build && node dist/cli`.
- Minimal: no frameworks, no runtime dependencies in the Worker. highlight.js and the Geist fonts are bundled into static assets at build time.
- No comments unless the code would be misleading without one.
- Conventional commits with short messages.

## Model

- A paste is one R2 object `p/<id>` with everything else in `customMetadata` (strings): `at`, `t` (title), `name`, `lang`, `lines` (as readers see them: after ANSI/OSC stripping and `\r` overwrites, so an OSC spanning newlines or an invisible last line doesn't count), `bytes`, `tok` (≈ bytes/4), `ansi` (has ESC or another control character besides tab/newline/CR), `cr` (has a bare `\r`, not part of CRLF), `exp` (unix seconds), `del` (sha256 of the delete token), `enc`, `kind` (`multi`), `files`, `cmd`, `exit`, `dur`, `ed` (unix seconds of the last edit). A read is one R2 get. Single-file pastes can be edited in place by whoever holds the delete token (no versions or history; "edit as new" forks).
- IDs are 6 random characters from `A-Za-z0-9`, written create-only (`if-none-match: *`) so a new paste never overwrites an old one. The router also accepts `+` and `-` in ids, for imported wastebin links in the upstream alphabet; only the owner can choose an id (`?id=`).
- Multi-file: `p/<id>` holds a JSON index (`{ files: [{ name, lang, lines, bytes, tokens }] }`), each file is `p/<id>/<name>`. File names are canonical relative paths (no `.`/`..`/empty segments, no backslashes, and the first segment isn't `vs`, which `/<a>/vs/<b>` uses).
- Expiry is checked on read; an expired paste reads as 404 and is purged lazily. No cron, no lifecycle rules. Anonymous pastes never expire unless `ttl` is set.
- No live pastes: there's no Durable Object (the `v2` migration deleted the old `Live` class). `bin run` collects the command's output (redacted line by line, keeping the last 2 MB, or 5 MB with the owner token) and creates one paste when it exits, with `cmd`, `exit` and `dur` as query parameters.
- Delete: `DELETE /<id>` with `x-delete: <token>` (returned once to anonymous creators; the CLI keeps one file per paste in `~/.config/bin/deletes/`, the browser keeps it in localStorage) or the owner token. Compare secrets with `same()`.
- Edit: `PUT /<id>` with the paste's token in `x-delete` (or the owner token) and the new text. A `PUT /<name>` carrying neither `x-delete` nor `If-Match` is still a create (`curl -T`), so an owner edit without the token sends `If-Match: *`. Multi-file pastes can't be edited (`PUT` on one, or on `/<id>/<file>`, is a 400). `edit()` heads the object, checks the token against that head's `del` and `If-Match` against that head's revision, then runs `create()` on it: same caps, rate limits (charged like a create), stats and secret warnings; it keeps the metadata (`at`, `del`, `exp`, `cmd`, …; the name and lang unless `?name=`/`?lang=`, the title unless `?title=`), drops the old stats and sets `ed`. An encrypted paste stays encrypted (the body must be an envelope). The revision is `"<R2 etag>.<uploaded ms>"` (the content etag alone is the same for identical text with new metadata, or for a paste deleted and recreated with the same text), exposed as `ETag` on text, raw and `HEAD` responses and as `etag` in the viewer's data JSON (never as a header on HTML, whose bytes also depend on cookies). `If-Match` is `*` or a list of strong tags (weak tags never match); a mismatch is a 412. The put is always conditional on the object that was authorized, with or without `If-Match`: `uploadedAfter(t - 1 ms)` and `uploadedBefore(t + 1 ms)`, which pins that exact upload. Not `etagMatches`, because R2 (like HTTP) ignores `uploadedBefore` when `etagMatches` is given. A failed condition is a 412 too. The receipt is the create receipt with status 200 and `etag`. CLI: `bin edit` reads `/raw` (decrypting if `x-bin-encrypted`), opens `$VISUAL`/`$EDITOR` on a private temp file named like the paste, and uploads with `If-Match` only if the text changed; the draft is deleted only when unchanged or uploaded, otherwise its path is printed. `bin put` sends `If-Match: *` unless given `--if-match`. Both apply the paste secret rules.
- Browser editing (`web/edit.ts`, lazy-loaded as `/a/edit.*.js` on the first `e` or pencil click, with its CSS injected from the chunk): only for pastes the server marks editable by putting `etag` in the data JSON, which it does only for single-file pastes shown inline whose text has no control characters at all (`stripAnsi(body) === body`: no ANSI, no `\r`, so not CRLF either, since a textarea would change those bytes) and that aren't encrypted, so the browser can never send plaintext for an encrypted paste. The header slot left of the icons (absolutely positioned, so revealing it shifts nothing) shows the pencil when this browser holds the token and the paste is editable, otherwise the delete button; delete for editable pastes is in the edit bar. `e` edits when the pencil shows and forks otherwise; `E` (the footer key) always forks. On touch screens up to 400px the download icon is dropped so the pencil never covers the id. Edit mode hides `#text` and puts a `textarea.code` in its place with the same font, line height and left padding (`field-sizing: content`, or `rows` where unsupported, and `-24px` bottom margin when the text ends in a newline, since a textarea shows that empty line and the viewer doesn't), so on desktop nothing moves. Touch screens switch to 16px text (iOS zooms smaller inputs): rows stay 24px, but wrapped lines rewrap and what's below can move, and the browser scrolls the caret into view. The caret starts on the first fully visible line (below the edit bar on touch). A markdown paste shown formatted switches to the source to edit and back afterwards. The edit bar (delete, Save, cancel) is a fixed `.find` box, right-aligned at the bottom on desktop and at the top on touch. Ctrl/Cmd+S saves, Esc cancels (confirm only if changed); a `beforeunload` guard is attached only while there are unsaved changes. Saving keeps the textarea read-only until the viewer has re-rendered and the editor has closed (re-enabled only on failure, with the error in a toast), updates the line count, refetches `/raw` with `cache: "reload"`, and records the new etag in `history.state`; a page restored from the HTTP cache by back/forward with another etag reloads itself. Size and "edited …" are rendered by the server on the next load.
- Owner: `Authorization: Bearer <BIN_TOKEN>` lifts the size limit (2 MB → 5 MB), the file cap (10 → 50) and the rate limits, and allows `?id=` and `?expires=`. Anonymous creates go through two rate-limit bindings: `ANON` (about 20 a minute per IP, IPv6 keyed by /64, per location; multi-file creates are weighted by file count) and `ANON_BYTES`, a shared budget for all anonymous pastes charged `max(R2 writes, 64 KB units)` per create (40 a minute per location, about 2.5 MB), which bounds storage growth and Class A ops since R2 has no free-tier hard stop. Request bodies are read with a byte cap (`readBounded`), never buffered whole first.
- Encrypted pastes are encrypted client-side (browser or CLI): `{ v: 1, kdf: "pbkdf2-sha256", iter, salt, iv, ct }`, AES-256-GCM with the tag appended to `ct` (WebCrypto's layout). The server stores the envelope and can't read it; slices and digests refuse them.

## Serving

- `HEAD` on a paste is one R2 `head` (agent headers, no body).
- One URL, two audiences: `wantsHtml()` sends the viewer to browsers (`Sec-Fetch-Dest: document`) and chat unfurlers (by user agent), and plain text to everything else. Agents get the text with ANSI escapes and `\r` overwrites resolved; `/raw/<id>` and `/dl/<id>` are always the exact bytes. `/<id>.<ext>` is the same paste; the extension only matters to the browser viewer when the paste has no language (`/<id>.md` of an untyped paste shows formatted markdown, `/<id>.py` highlights Python). With no name or lang, create detects diffs, shebangs, ANSI logs and markdown (a `#` heading on the first line plus another heading or a code fence in the first 2 KB).
- Agent responses carry `x-bin-lines`, `x-bin-bytes`, `x-bin-tokens`, `x-bin-lang`, `x-bin-title`, `x-bin-name`, `x-bin-command`, `x-bin-exit`, `x-bin-duration-ms`, `x-bin-expires`, `x-bin-edited`, `x-bin-encrypted`, and `x-bin-hint` above ~10k tokens.
- Agent reads of plain pastes (no ANSI, no `\r`, not encrypted, no slice) stream the R2 body untouched: no decode, no CPU. Everything else is decoded (keeping a leading BOM, unlike `obj.text()`) and cleaned with `stripAnsi` (one regex pass, then `\r` overwrites and stray control characters).
- Slices (`lines`, `head`, `tail`, `grep` + `context`, `n=1`) and `digest` are plain text even for browsers. `grep` output matches `grep -n -C`. `grep` is not a regex (user regexes can blow the CPU budget): text, `|` for alternatives, `^`/`$` anchors, `.*` wildcards, `\` escapes punctuation; case-insensitive unless the pattern has capitals; matched linearly with `indexOf`. The digest is rules, not AI: error/warning/summary regexes, error blocks extended over more-indented lines and stack frames, near-identical lines collapsed by normalising numbers and hex, then the tail; every item has line numbers.
- `/<a>/vs/<b>` is a Myers line diff of the middle after trimming the common prefix and suffix (refused over 500 KB or 5,000 lines a side, checked from metadata before reading; "too different" past 500 edits), served like a `diff` paste. Like `diff -u`, a side without a final newline gets `\ No newline at end of file` after its last line (so `hello` vs `hello\n` differs), and hunk ranges are `-1` for one line and `-0,0` for an empty side.
- Server-side secret scanning only reads the first 256 KB and pre-tests one combined regex. The CLI refuses or `--redact`s before uploading, and `bin run` redacts its output line by line (a private key block is masked through its END line) and the recorded command.
- The viewer page is a shell: the text goes in `<pre id="text">` (ANSI stripped, so it reads fine without JS and for HTML-fetching agents), the original goes in `<template id="ansi">` (with `\r` as `&#13;`) only when it has ANSI codes, pastes over `INLINE_MAX` (512 KB) aren't inlined (the page fetches `/raw`, or `/<a>/vs/<b>` for big diffs), and `view.js` renders rows in the browser, 256-line blocks at a time: blocks far from the viewport hold their plain text (same height, wrapped or not) and get rows when they come within 1500 px. The Worker never renders lines: Workers Free has a 10 ms CPU budget, and a 1 MB log must cost only an R2 read, an escape and a JSON encode.
- Nothing pasted is ever rendered as HTML as written. Raw text is `text/plain` with `nosniff` and `content-security-policy: sandbox`; pages have `script-src 'self'`, `style-src 'unsafe-inline'` (inline CSS), `img-src 'self' data:` plus `https:` only on markdown pages and the compose page (which can show a markdown paste in place after saving), `'inline-speculation-rules'` (multi-file tab prefetch) and `frame-ancestors 'none'`. All paste text reaching the DOM goes through `esc()` or highlight.js (which escapes); in markdown, raw HTML is rebuilt by `md.ts` from a fixed allowlist (below), never passed through.
- Markdown: a paste (or file) with lang `markdown` (`.md`/`.markdown` names, or `--lang markdown`) opens formatted in browsers; agents, curl, `/raw`, slices and digests are unchanged. The server marks the page (`mdp`, plus `fmt tall` when formatted), inlines `md.css`, hides `#text` with CSS (a `<noscript>` style shows it again), modulepreloads `md.js` instead of the source's highlight.js modules, and serves `view-md.js`. `md.js` parses with marked's lexer and renders the tokens itself: every tag and attribute comes from `md.ts`, all text is escaped, character references are decoded per CommonMark first (named ones through a detached `<textarea>` on the main thread, passed to the Worker as a map; schemes are checked after decoding), link hrefs must be `http(s):`, `mailto:` or `#` (rewritten to `#md-…`), or a relative path to another file of the same multi-file paste (`/<id>/<file>`), image srcs `https:` (`http:` is upgraded), links get `rel="noopener noreferrer nofollow ugc"`, images `loading=lazy decoding=async referrerpolicy=no-referrer` and alt text from the parsed label, heading ids are unique slugs prefixed `md-`. Raw HTML (blocks and inline) is rebuilt, not passed through: a tag regex picks out tags, comments are removed, `script`/`style`/`textarea`/`title`/`template`/`noscript`/`iframe`/`svg`/`math` are removed with their content, other tags outside the allowlist (`a b blockquote br code del details div em h1`–`h6 hr i img ins kbd li mark ol p pre s small span strong sub summary sup table tbody td tfoot th thead tr u ul`) are dropped (their text stays, escaped), and the only attributes kept are `href` (a) and `src` (img) through the same URL checks, `alt`/`title`, numeric `width`/`height` on images, `align` as an `al-*` class and `open` on `details`; tags are balanced, and a container left open by an HTML block (a `<details>` TOC, a centered `<div>`) wraps the markdown after it until it closes (at most ~64 KB, then it's closed). GitHub alerts (`> [!NOTE]`, `TIP`, `IMPORTANT`, `WARNING`, `CAUTION`) get a coloured title from CSS; ```` ```diff ```` fences colour `+`/`-`/`@@` lines. Texts over 64 KB are parsed and highlighted in a module Worker (the same `md.js`); HTML goes into the page in ~32 KB chunks, one per frame, so no task runs long. A top-level list, table, blockquote or fence whose HTML is over 32 KB goes in as an empty shell plus its items, rows, children or ~32 KB line-aligned code pieces, 16 KB per frame; lists continue in sibling lists (`start` and margins keep them seamless) and tables in sibling tables with the column widths of the first piece frozen (`table-layout: fixed`), because appending to one long list or auto-layout table costs time proportional to its size. A single item that is itself huge (one list item holding a 500 KB nested list) still goes in at once. Any failure (a marked stack overflow on deeply nested input, an exception, or the Worker taking longer than 3 s + 1 ms per KB) shows the source with a toast; toggling never waits for unfinished formatting. The compose page's in-place view uses the plain viewer if `md.css` fails to load. Fenced code with a known language loads only that language's highlight.js module. `m` (or the header `<>` button, or the footer button on touch) toggles source/formatted and keeps the reading position (the top line, interpolated within the block, so it doesn't drift inside long lists, tables or code); the formatted position is kept in `history.state` (300 ms after scrolling stops, and on `pagehide`) with `scrollRestoration = "manual"`, so a reload or back/forward lands where you were; `w` does nothing while formatted; on touch phones the header drops the download icon (and raw up to 400px) so the id fits; the choice is the `md` cookie (`0` = source), read by the server so there's no flash. `#L` links, `g` and `/` switch to the source without changing the cookie. The formatted view's height is unknown until it renders, so markdown pages are `tall` (the footer starts below the fold); images are the only accepted layout shift.
- Scrollbars: the page and every scroll container inside it (`:root, body *`, plus the select pickers) get `scrollbar-width: thin` in `--gut` on transparent (`--edge` is too faint on the `--soft` code background); `scrollbar-gutter: stable` keeps the width fixed so nothing shifts.
- Theme: dark by default; the `theme=light` cookie (set by the toggle or `t`) makes the server render `data-theme="light"`, so there's no flash. The `wrap=1` cookie works the same way for line wrapping.
- Successful reads of raw, dl, slices and agent text are `private, max-age` ≤ 300 (and never past expiry), so refetches are free; an edit or delete reaches them within 5 minutes. Paste pages (HTML) are `private, no-cache`, so a reload or a new visit always shows the current version; back/forward may still show the cached page (the editor's own tab reloads it, see above). Everything else is `private, no-cache`.
- Phones: `viewport-fit=cover` with `env(safe-area-inset-*)`, heights in `svh` (plain `vh` is the large viewport on iOS, so a 100vh page scrolls), form controls 16px and 44px tall on `(pointer: coarse)` (iOS zooms into smaller inputs; never `maximum-scale`), and `≤640px` layouts (compose Save and status move into the header row). Hover styles go under `(hover: hover)`. Keep desktop pixel-identical when changing these.
- Every response is `cache-control: ... no-transform` (Cloudflare otherwise injects scripts into HTML), `x-robots-tag: noindex`, `referrer-policy: no-referrer`.

## Cost (Workers Free)

- Create: 1 request, 1 R2 put (multi-file: 1 + one per file), 2 rate-limit checks if anonymous (3 for multi-file). The stats (`lines`, `ansi`, `cr`) are one pass over the bytes four at a time; only pastes with control characters or a bare `\r` also scan for OSC sequences spanning lines and strip the last line. Free limits are per account and daily (100k Worker requests), shared with tack and the other Workers.
- Edit: 1 request, 1 R2 head + 1 put, 2 rate-limit checks if anonymous; the browser then refetches `/raw` once (1 request, 1 get) so its cache isn't stale. Paste pages are revalidated on every visit (1 request, 1 get each).
- View or slice: 1 request, 1 R2 get (multi-file: 2; pastes over 512 KB: a second request for `/raw`). Static assets cost no Worker invocation. Markdown is parsed in the browser; the Worker only adds a class and inline CSS.
- Expired pastes: purged (free deletes) when someone asks for them; a multi-file purge reads its index rather than listing.
